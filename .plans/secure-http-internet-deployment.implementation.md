## Out-of-scope discoveries

- Environment at session start: Node v26.13.0 (Windows), WSL2 Ubuntu kernel 6.18 with Node 22.22.1 and PureBasic 6.41 at `~/Apps/purebasic-v641`; Caddy not installed on either OS (fetch/acquire in T5 if available); dirty tree matches the prior plan's recorded end state.
- **Accidental generated artifact overwrite:** A malformed PowerShell invocation during T2 ran `build.cmd` without `PBMCP_OUT` and rebuilt root `pbmcp.exe`. Its exact prior contents were not backed up; no plausible candidate was substituted because the prior binary differed in size from the known `dist`/`tmp` candidates. Root `pbmcp.exe` is ignored/generated and currently contains the T2 build; all later work uses explicit candidate outputs. Surface this at delivery; do not guess a restoration.
- **Upstream Caddy checksums.txt inconsistency (T5):** the v2.10.2 release's own `checksums.txt` does NOT match the published archives. Verified not to be local tampering: repeated downloads reproduce byte-identical files, the archives are valid with original 2025-08-23 build timestamps, and the GitHub API per-asset `digest` fields match the downloaded artifacts exactly (windows zip `sha256:9fd1ef9be5d9b05852b66ccc25f96f23d8651bcab20779861a745bdffa273722`, linux tar.gz `sha256:5c218bc34c9197369263da7e9317a83acdbd80ef45d94dca5eff76e727c67cdd`). Treat GitHub's API digest as the verification source for the recorded stock release and note this in the release evidence.
- **GitHub API from scripts:** requires a `User-Agent` header or it returns empty responses (cost one debugging round).
- **T6 session: server crash on unknown JSON-RPC method (fixed in scope):** first full-suite run against the auth-enforcing binary crashed on `unknown/method` (silent exit, no audit event, no stderr). Root cause: `GetJSONMember(replyResult, "isError")` with `replyResult = 0` when the reply carries `error` instead of `result`. Lesson: T1–T4 verify used per-group `--test-name-pattern` runs; the crash lived in the http-protocol group that no pattern run had exercised since T2 landed auth. Full-suite runs are the only complete evidence.
- **run_tests `[C]` exe-adjacent-index gotcha:** run_tests without `PBMCP_EXE` tests root `pbmcp.exe`, which sits next to the repo-root `index-6.40.json`; group [8][C]'s exe-adjacent discovery then loads a real index and `[C] placeholder loads but reports no-index` fails deterministically. Chain runs with `PBMCP_EXE=<tmp candidate>` → 152/0. Always export `PBMCP_EXE` when running run_tests against a candidate.
- **Transient AV staging failures:** immediately after a candidate rebuild, `hints_sub`/`hints_protected` failed once with `cannot open project file for reading` (Defender scanning freshly written files); passed on every later run. Same transient-lock mechanism as the T5 Caddy scratch EPERM. Do not chase single-run staging/read failures right after a rebuild; rerun once and record if persistent.
